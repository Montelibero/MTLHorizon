# Отчёт по этапу 06: админка, исторический API и готовность MVP

Этап 06 продолжил проект после этапа 05 (миграция `0010`, 588 тестов). Сделаны
три блока задания: админка, из которой владелец управляет установкой через
браузер; исторический API — совместимое подмножество REST Horizon, читаемое
из своего архива; и то, что держит их вместе — долговечные задачи для всего,
что занимает время, фоновый проход воркера по расписанию и счётчики импорта.

Кратко:

- **875 тестов** на настоящей PostgreSQL 17, без внешней сети (было 588).
- **0 внешних HTTP-запросов** за этап. Всё проверено на встроенных Horizon и
  Notifier; живой Notifier и живой Horizon не трогались.
- **Живая интеграция с Notifier не проверена** — это выходной барьер. Смоук-тест
  приготовлен (`python -m app.smoke`), запускается только с разрешения
  владельца. До его прохождения установка готова к пилотному запуску, не к
  production.
- Миграции `0011`–`0012` проверены на копии пилота (с `0003`), на копии dev-базы
  (с `0010`), с откатом и повторным накатом; история не тронута; backup/restore
  сходится по слепку.
- Единственная новая зависимость — `jinja2` (из локального кэша, без сети).

## 3. Админка

**Дверь.** Без секрета админка закрыта для всех, и страница входа так и
говорит (fail closed). Сессия — строка в базе с хешем случайного токена;
токен живёт только в cookie: `HttpOnly`, `SameSite=Strict`, `Secure` при
заданном публичном origin, отдаётся только для `/admin`. У каждой формы,
меняющей состояние, токен (HMAC от секрета сессии): POST без него — 403, и
ничего не меняется. С заданным `MTL_HORIZON_PUBLIC_ORIGIN` изменяющий запрос
обязан прийти с этого origin. Неудачные входы считаются по адресу и по всем
сразу: пятый блокирует адрес на 15 минут, повторное блокирование дольше.
**GET ничего не меняет.**

**Страницы** — подробная таблица в `docs/architecture.md`, раздел 33; как ими
пользоваться — `docs/owner-runbook.md`, раздел 14. Здесь — главное:

- Дашборд отличает пустую очередь от остановленной службы по heartbeat; числа
  помечены «точно / оценка / неизвестно» с временем измерения.
- Импорт истории показывает аккаунты и рынки **порознь**, причины ожидания,
  долю завершённых субъектов с названным знаменателем, по каждому заданию —
  четыре потока с покрытием и пробелами, прочитанное и добавленное порознь.
  ETA, число непрочитанных записей и дата по среднему времени леджера не
  вычисляются.
- Обозреватель читает Horizon только по явному запросу; прочитанное не
  хранится.
- Любое изменение — та же сервисная функция, что зовёт команда этапов 02–05.

**Проверка глазами.** Сквозной тест (`tests/test_e2e_ui.py`) при
`MTL_HORIZON_UI_DUMPS=<каталог>` сохраняет главные страницы как они
отрисовались с данными; они сведены в картинки (`local/reports/ui/*.png`, в git
не попадают) и просмотрены: дашборд, импорт, график, Notifier (в норме и с
лежавшим Notifier), аккаунты, discovery, задача. Замечания с этого просмотра
исправлены (задвоенное «истории» в заголовке службы, сырые имена полей
heartbeat). Авторами страниц при таком же просмотре найдены и исправлены
свои: пустой `<svg/>`, наложившиеся подписи, таблица, сжатая до символа в
строку, вложенные ссылки в списке рынков. Мобильная ширина (390 px)
проверена на дашборде и графике: навигация переносится, таблицы
прокручиваются.

## 4. Исторический API

Полное описание — [`history-api.md`](history-api.md). Матрица совместимости:

| Маршрут | Есть у upstream | Что здесь |
| --- | --- | --- |
| `/accounts/{id}/transactions`, `/operations`, `/effects`, `/trades` | да | по участникам; сделки с двух сторон; расширение: фильтр операций по типу и по данным `manage_data` |
| `/transactions`, `/operations`, `/effects` | да (весь поток сети) | локальная выборка архива по курсору; `scope` говорит об этом в ответе |
| `/transactions/{hash}` | да | fee-bump по внешнему и внутреннему хешу |
| `/transactions/{hash}/operations`, `/effects` | да | |
| `/operations/{id}`, `/operations/{id}/effects` | да | |
| `/trades` | да | архив или рынок в заданной ориентации |
| `/trade_aggregations` | да | формулы этапа 03, корзины UTC, обе ориентации, сделки пулов; пустые интервалы не выдумываются |
| `/v1/coverage` | нет | расширение: покрытие и контекст субъекта с явной неполнотой |
| `/ledgers`, `/accounts/{id}`, `/assets`, `/offers`, `/payments`, SSE | да | не сделаны и не выдаются за совместимость |

Доступ: `token` по умолчанию (`Authorization: Bearer`), без заданных токенов не
читает никто (403), неверный — 401; `open` — все. Ссылки указывают на эту
установку. Формы записей сверены с семью сохранёнными ответами живого Horizon
(этапы 02–03) и с вырезкой живых агрегатов; живых запросов на сверку не было.
Отклонения от upstream перечислены в `history-api.md`, раздел 13 (ссылки на
ресурсы, которых здесь нет, дают 404 приложения; 401/403 — `about:blank`;
coverage не отдаёт хост источника). EXPLAIN на синтетических данных: все
страницы идут по индексам; для потоков аккаунта bitmap-сканы выключены на
время одного запроса (планировщик ошибался в 10 раз и читал всё); на
реальных объёмах планы не измерялись.

## 6. Очередь истории

Счётчики, приоритет и пауза — раздел 36. Счётчики хранящейся страницы пишутся
в одной транзакции со страницей (хук `Backfill.on_page_stored`), так что сбой
между записью и подсчётом не может солгать; живой сбор в них не входит. Один
срез — одна структурированная строка лога. Приоритет — очки: N очков выглядят
как «обслужен на N×10 минут раньше»; приоритетный получает больше срезов,
остальные — свои. Общая пауза живёт в базе, не трогает live и переживает
рестарт.

Найдено и исправлено по ходу: импорт рынка ставился на паузу с причиной
аккаунта, и после повторного включения рынка оставался на паузе навсегда —
теперь причина своя у каждого вида, и проход сам возвращает задание в работу.

## 7. Notifier

- **Сверка по факту.** Раз в 10 минут и при ручной сверке список у Notifier
  читается снова: своя подписка, пропавшая там, регистрируется заново один
  раз и с растущей паузой; сделанная вручную помечается `ambiguous`, взамен
  ничего не создаётся. В этапе 05 такая подписка навсегда оставалась
  «активной» здесь.
- **Что там сейчас** — `reconcile.plan()`: список у Notifier и что сделала бы
  сверка, без единой записи. Кнопка на странице и dry run команды.
- **v0.13.0.** Читатель уведомлений понимает muxed-поля рядом с адресами,
  долю пула (`asset_type: 3`) и пару активов пула (`assets`, `pool_assets`).
  Сверено с кодом двух ревизий и примерами `RESPONSE_EXAMPLES.md`; живых
  доставок не было.
- **Смоук-тест** (`python -m app.smoke`): `status` (2 запроса), `subscribe`
  (одна тестовая подписка), `watch` (ждёт доставку и конец задания, читая
  журнал), `unsubscribe` (удаляет только её). На встроенном Notifier
  проверен; на настоящем не запускался.

## 9. Надёжность: что проверено и что найдено

| Проверка | Что оказалось |
| --- | --- |
| Provisioning под потоком событий | голодал; исправлено (раздел 5) |
| Курсор открытий trustline | по времени завершения задания: транзакция, завершёншаяся на два часа позже среди ежеминутных просмотров, находится; повторно не добавляет. Запас 5 минут покрывает расхождение часов до 5 минут |
| Deadlock (40P01, 40001) | advisory lock писателя — не защита от циклов: в цикле «строка против advisory lock» PostgreSQL обрывает писателя истории, он ждёт первым. Воркер событий и очередь истории повторяют такую попытку сразу (2 с), попытка считается — не бесконечно |
| 2 воркера событий, 2 службы истории, проходы и discovery одновременно | слепок равен последовательному импорту тех же доставок и окна; `count(*) = count(distinct id)`; аренд не зависло |
| Неизвестный формат уведомления, 503 одного потока, 410 и смена Horizon, остановка посреди страницы, продолжение из чекпоинта, повторная постановка | тестами этапов 04–05, остаются зелёными |
| Подписка, выключенная снаружи | не была видна; исправлено (раздел 7) |
| Пауза импорта рынка | с чужой причиной, навсегда; исправлено (раздел 6) |
| Случаи v0.13.0 (пулы, депозит/вывод, сделки пула, пассивные офферы, правила v2) | читаются читателем; чего Notifier не покрывает (тип операции, которого не знает его SDK; неявные изменения без операции) — показано на страницах рынка и актива как ограничение |

остановка, после них службу поднимает владелец. Проект удалён, dev-установка
не тронута.

## 13. Инциденты и ошибки

**Лимит планы оборвал трёх субагентов.** Страницы писали три субагента
параллельно со статистикой; лимит использования плана остановил всех троих
на середине. Два возобновлены с сохранённым контекстом и донесли своё; третий
— страницы импорта истории — на сообщения не ответил, его часть доведена
здесь: код и 13 его тестов уже были на диске, проверены и приняты. Часть
страниц могла бы быть просмотрена их авторами внимательнее — просмотр глазами
сделан здесь (раздел 3).

**Дефекты, найденные проверками этапа** (все исправлены): голодание
provisioning; подписка, выключенная снаружи; пауза импорта рынка с чужой
причиной; писатель истории — жертва deadlock’а; «продолжить» discovery вело бы со старого места после
полного прохода; ссылки пагинации ломались на `& # %`; `MTL_HORIZON_HISTORY_CONTEXT`
не передавался в контейнеры.

**Мои ошибки по ходу:**

1. Тест конкурентности сравнивал базу с чистым backfill, а живые события
   приносят больше, — эталоном стал последовательный импорт тех же доставок.
2. Первый сквозной тест взял держателей, которых встроенный Horizon не знает
   (404 на каждом потоке), и «широкий» период агрегатов указал в миллисекундах
   как в секундах — обе пустоты выглядели как дефект API, а были ошибкой теста.
3. `docker compose kill` принят за аварию; на самом деле это явная остановка.
   А `kill -9 1` изнутри контейнера ядро игнорирует — «упал с 137» показан
   только на мягком завершении. В отчёте этапа 04 фраза про «убив процесс
   внутри контейнера» была неточной — поправлена там.
4. `support.page()` принимал `login` и `active` ключевыми словами и конфликтовал
   с переменными страниц; стали позиционными.
5. В отчёте по статистике отмечено, что первый прогон её тестов падал из-за
   правок соседнего субагента в этот момент — перегнан, зелёный.

## 14. Ограничения и остаточные риски

- **Живой Notifier — выходной барьер.** Форма уведомлений, подпись и
  автоматическая регистрация проверены на встроенном Notifier, не на
  настоящем.
- **Адреса за прокси.** Счётчик входов видит адрес прокси: пять неудачных
  входов от любого читателя за одним прокси блокируют всех на 15 минут.
  `X-Forwarded-For` не читается (подделывается); решение за владельцем.
- **Стоимость среза растёт с размером списка** (218 мс на 5000 субъектов);
  при темпе 1 запрос/с — доли процента. Не оптимизировано.
- **Скорость импорта** по времени записи читает таблицы без индекса по
  `created_at`; таблицы больше 256 МиБ пропускаются и говорят об этом.
- **Исторический API**: планы и таймаут (10 с) измерены на синтетике; агрегаты
  за длинный период могут не успеть — тогда 503; bitmap-сканы выключены для
  потоков аккаунта; живьём не сверялся.
- **Кэш дорогих счётчиков** дашборда — в пределах процесса.
- **Страницы очереди событий в админке нет** — ошибки видны блоком на
  дашборде и командой `python -m app.worker events`.
- **Русские подписи к цифрам статистики** живут в модулях страниц; источник
  английских формулировок — `app/stats`; могут разойтись.
- **График** — статический SVG, без интерактивности.
- **Живые ответы v0.13.0** не сверялись с настоящими доставками.
- Остальное — `docs/architecture.md`, раздел 41; ограничения полноты —
  раздел 22 (этап 04) без изменений.
