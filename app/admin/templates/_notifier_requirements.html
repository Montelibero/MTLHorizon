Что требуется от Notifier — и что здесь неизвестно

Лимиты — требование, а не факт о сервисе

У Notifier должны быть достаточно велики MAX_ACTIVE_SUBSCRIPTIONS и MAX_ACTIVE_SUBSCRIPTIONS_PER_USER (по умолчанию 100): этой установке нужно {{ wanted | num }} активных подписок, а в общий лимит входят и чужие. Какие значения стоят у вашего Notifier — фактические значения здесь неизвестны: через API их не узнать, проверьте в конфигурации Notifier. Когда лимит исчерпан, Notifier отвечает отказом, и строки остаются в error с причиной, пока лимит не поднимут.

В режиме авторизации disabled все подписки принадлежат одному анонимному администратору, и лимит на пользователя считается на всех вместе.

Авторизация

Поддерживаются режимы disabled (без токена) и token (токен в X-Access-Token или Authorization). Режим с ed25519-подписью каждого запроса по nonce не поддерживается: там подписки делаются вручную и принимаются здесь по id.

Ключ подписи — не токен API

Ключ подписи вебхуков (MTL_HORIZON_NOTIFIER_KEYS) и токен API (MTL_HORIZON_NOTIFIER_API_TOKEN) — две разные вещи. Ключ — публичный ключ Stellar, которым Notifier подписывает уведомления: по нему установка проверяет, что вебхук пришёл от своего Notifier. Токен — секрет, которым установка представляется API Notifier; на страницах он не показывается.

Подтверждение — не гарантия доставки

Подтверждённая подписка не гарантирует, что уведомления не прекратятся. Notifier повторяет доставку, затем бросает и выключает подписку — установки об этом никто не сообщает. Заметно это становится, когда проход читает список у Notifier: «Что там сейчас?» проверяет фактическое состояние, а не местный статус.

Сделанное руками не удаляется здесь

Подписку, созданную человеком, эта установка никогда не удаляет — сделал человек, удаляет человек. Здесь её можно только забыть (release): у Notifier она останется. На этой странице нет способа удалить подписку.
